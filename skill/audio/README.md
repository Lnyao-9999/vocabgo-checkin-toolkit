# 音频识别子模块（听音频选中文题用）

目标：让代理"听见"手机投屏里播放的英文单词，并在 4 个中文选项里定位正确答案。

**不下载任何语音识别模型。** 全部靠：Windows 自带英文 TTS（Zira）合成候选词 → 与现场录音做 MFCC + DTW 比对。

## 依赖（仅两个小包，约 25MB）

```powershell
python -m pip install --only-binary=:all: -i https://pypi.tuna.tsinghua.edu.cn/simple numpy sounddevice
```

（必须加 `--only-binary=:all:`：Python 3.15 上直接装可能触发源码编译；pypi 官方源在国内很慢，用清华镜像 9 秒装完。）

## 关键结论：录哪里

| 采集源 | 实测效果 |
|---|---|
| **WASAPI loopback（内录）**：把「电脑扬声器 (… output with SST)」当输入设备 | ✅ 最佳。rms≈0.2、无需放大、100% 识别 |
| 立体声混音 (Stereo Mix) | 可用但很轻（rms 0.005），要放大 |
| 麦克风阵列（mic 实测） | ❌ 太吵/太轻：4 词测试仅 1/4，不可用 |

内录成立的前提：**手机投屏的声音确实从电脑扬声器出来**（vivo 办公套件投屏默认会同步声音；若手机声音只从手机外放，则只能回到麦克风方案，命中率会明显下降）。

## 用法

```powershell
cd <包目录>\audio

# 1) 生成候选词模板（每个词一个 wav，16k 单声道，Zira 读音）
#    —— 包内 templates\ 已预生成 32 个高频词，缺词时用 tools\tts_words.ps1 补

# 2) 在手机上点「▶播放」的同时录音并打分（--seconds 要覆盖词的时长，3 秒足够）
python listen.py --seconds 3 --device loopback
# 输出（JSON）：
# {"device":"电脑扬声器 (Realtek HD Audio Output with SST)","rms":0.21,"peak":0.74,
#  "dur":0.62,"ranking":[{"word":"beam","dist":0.49},{"word":"midst","dist":2.1}, ...]}
# ranking[0] 就是识别结果；dist < 1.0 视为高置信，> 2.0 大概率是没录到/环境噪声

# 3) 只想自测（用扬声器播 TTS 再录回来验证链路）
python selftest.py --words beam,midst,groan,compliment --device 15 --reps 2
```

## 实测数据（本机）

```
自测（TTS→扬声器→内录）：8/8 = 100%，正确词 dist≈0.5，错误词 dist≈2.0+（区分度极大）
同一录音改用麦克风阵列：0/4 ~ 1/4（放弃）
```

## 拿到词之后怎么点

1. 词达人「听音频题」的 4 个选项是**中文释义**，所以还要：识别出英文词 → 在 `词汇表.md` 里查它的中文 → 与页面 4 行中文做包含匹配 → 得到行号；
2. 行号 → 坐标：4 行按钮纵向排列，`x=232`，`y = 341, 407, 472, 538`；
3. `pz.ps1 click -X 232 -Y <y>`，再截图确认是否出现「✓」或页面显示 `播放 <word>`。

## 兜底顺序（识别置信度不够时）

1. **选项集合启发式**（不录音也能用）：本组只练 4 个词，4 个中文选项里只有属于这 4 个词的那个才可能是答案；恰好唯一时直接点，命中率极高。
2. 若同时有 2 个候选 → 用 `listen.py` 的录音结果打破平手；
3. 仍不确定 → 问用户（用户能听见），或先猜一个（答错会进单词详情卡，流程仍可继续，只是扣分）。

## 已知限制

- 内录要求音频走电脑扬声器；戴耳机听手机（蓝牙直连手机）时内录为静音。
- 录音与点击「▶播放」的时序要错开约 150ms，否则可能录不到开头。
- 若页面在点击播放前不给任何文字，录音是唯一信息源；录制窗口建议 2.5~3 秒并保留 0.2 秒前导。
